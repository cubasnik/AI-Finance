# RULES — Права доступа пользователей

_Последнее обновление: 26.07.2026, 14:27 (МСК)_

Этот файл фиксирует, что может делать каждая роль в системе AI Finance.
Обновляется при каждом изменении прав доступа.

---

## Роли в системе

| Роль (техническое имя) | Отображается как | Кто это обычно |
|---|---|---|
| `owner` | Владелец | Собственник бизнеса, полный доступ |
| `accountant` | Главный Бухгалтер (ГБ) | Ведёт финансовый учёт |
| `user` | Обычный пользователь | Делопроизводитель, юрист, менеджер и т.д. — любой сотрудник без специфичных финансовых прав |

Роль назначается в панели **"👤 Пользователи"** (доступно Владельцу и Главному Бухгалтеру).

### Должности с правами Главного Бухгалтера

**Операционный Директор (ОД)** и **Директор по Контролю (ДК)** — это **должности** (поле "Должность" в профиле
пользователя), а не отдельные системные роли. Технически им назначается та же системная роль `accountant`,
что и Главному Бухгалтеру — поэтому их права **полностью идентичны** правам ГБ (см. таблицу ниже), без
необходимости поддерживать отдельную логику прав для каждой должности.

Если понадобится добавить ещё одну похожую должность с такими же правами — достаточно назначить
пользователю роль `accountant` и указать нужную должность в профиле, отдельно менять код не требуется.

## Общий принцип

- **Просмотр и скачивание** (Excel/PDF) — доступны **всем ролям** во всех разделах управления.
- **Добавление / редактирование / удаление** — регулируется по разделам ниже.

## Обоснование ключевых решений

- **Лимиты бюджета — исключительно у Владельца.** Это стратегический финансовый параметр (бюджетные рамки компании), по прямому запросу владельца изменять его может только он, независимо от роли остальных.
- **Главный Бухгалтер (ГБ) получил полные права почти везде** (включая Организации, Банковские счета, Пользователей, удаление записей) — по прямому решению владельца, чтобы бухгалтер мог полноценно вести учёт без постоянных согласований.
  - ⚠️ **Важно понимать последствие:** это означает, что Главный Бухгалтер может создавать/редактировать/удалять **других пользователей системы**, включая их роли (кроме превращения кого-либо во Владельца при единственном текущем владельце — это заблокировано отдельной защитой). Если это нежелательно — можно вернуть эти права только Владельцу, сообщите об этом.
- **Обычный пользователь видит, но не редактирует Сотрудников, Доп. соц. пакет, Заказчиков и Продавцов.** Ему доступен просмотр списка и скачивание в Excel/PDF, но добавлять/менять/удалять записи может только Владелец, Главный Бухгалтер (и должности с его правами — ОД, ДК). В разделе "Сотрудники" дополнительно скрыты столбцы Официальная ЗП / Неофициальная ЗП / Итого — их видят только Владелец и Главный Бухгалтер.
- **Обычный пользователь (Обычный пользователь / Делопроизводитель)** сохранил полные права редактирования только в разделе "Табель посещаемости" — это соответствует его фактической рабочей задаче (учёт посещаемости). Во всех остальных разделах управления — только просмотр и скачивание отчётов, без права что-либо менять или удалять.

## Как менять права в будущем

Права проверяются в двух местах одновременно (важно менять оба, иначе они разойдутся):

1. **Сервер** (`server.js`) — фактическая защита данных. Используются функции:
   - `requireAuth` — любой авторизованный пользователь (любая роль)
   - `requireEditor` — Владелец или Главный Бухгалтер / ОД / ДК (не "Обычный пользователь")
   - `requireOwner` — только Владелец
2. **Интерфейс** (`dashboard.html`) — визуальное скрытие кнопок для соответствующих ролей (CSS-классы `body.role-owner` / `body.role-accountant` / `body.role-user`). Это не защита данных сама по себе (это делает сервер), а просто чтобы не показывать кнопки, которые всё равно не сработают.
